# JAAD Logistics ERP — backend

A real Next.js 16 app wired to Supabase (Postgres, Auth, Row Level Security).
No fake data, no mock functions. All 12 modules are fully wired end to end:
Dashboard, CRM & Leads, Customer Management, Shipment Operations, Fleet,
Driver Management, Warehouse, Finance, HR & Careers, Support, Reports, and
Administration.

## What's actually real here

- **Schema** (`supabase/migrations/0001_schema.sql`): every table for all 12
  modules. Tested against a real local Postgres instance before this was
  written up, not just hand checked.
- **Row Level Security** (`supabase/migrations/0002_rls.sql`): access is
  driven by each user's role and that role's `permitted_modules` array. A
  user without a module granted gets zero rows back and a rejected insert,
  enforced by Postgres itself. Tested with two simulated logged-in users,
  one with CRM access and one without, confirming both the block and the
  allow sides.
- **Tracking numbers**: generated by a database trigger from the pickup
  date, in the `JAAD/DDMM/YYYY/#####` format. The browser never sends one,
  so it can't be spoofed. Verified by actually inserting rows.
- **Reports**: `/api/reports/[category]` queries live data through the same
  RLS-protected client and streams back a real CSV, not a placeholder.
- **Seed data** (`supabase/seed/seed.sql`): the same sample customers,
  drivers, fleet, bookings, invoices, expenses, employees, inventory and
  tickets you already recognize from the prototype. Run against the real
  schema to confirm it inserts cleanly.
- Every module compiles clean under `npx tsc --noEmit` and a full
  `npm run build`, both run after every batch of modules, not just at the
  end.

## Setup

### 1. Create a Supabase project
Go to supabase.com, create a free project. Wait for it to finish provisioning
(a couple of minutes).

### 2. Run the migrations and seed data
In the Supabase dashboard, open **SQL Editor** and run these three files in
order, pasting each one's contents in and clicking Run:
1. `supabase/migrations/0001_schema.sql`
2. `supabase/migrations/0002_rls.sql`
3. `supabase/seed/seed.sql`

(If you'd rather use the Supabase CLI: `supabase link`, then
`supabase db push`, then run the seed file with `psql` against the
connection string in your project's Database settings.)

### 3. Get your project's API keys
In the Supabase dashboard: **Project Settings > API**. You need the
**Project URL** and the **anon public** key. Do not use the `service_role`
key in this app.

### 4. Set your environment variables
Copy `.env.example` to `.env.local` in this project's root, and fill in the
two values from step 3. Never commit `.env.local` or paste its contents
anywhere, including back into this chat.

```
cp .env.example .env.local
```

### 5. Install and run
```
npm install
npm run dev
```
Open http://localhost:3000. It will redirect to `/login`.

### 6. Create your first user and link it to a role
Supabase Auth users are separate from the app's `profiles` table on
purpose (`profiles` is what carries the role). Easiest path:
1. In the Supabase dashboard, go to **Authentication > Users > Add user**,
   create yourself with an email and password.
2. Copy that new user's UUID from the users list.
3. In **SQL Editor**, run (replacing the two placeholders):
   ```sql
   insert into profiles (id, full_name, email, role_id)
   select '<paste-the-user-uuid-here>', 'Your Name', 'you@jaadlogistics.com', id
   from roles where name = 'Super Admin';
   ```
4. Log in at `/login` with that email and password.

## Adding or extending a module
Every module follows the same three-file shape:
1. `page.tsx` — server component, queries Supabase directly, renders a table.
2. `actions.ts` — `'use server'` functions for create/update, calling
   `supabase.from(...).insert()/.update()`. RLS enforces who's allowed;
   you don't need to re-check permissions in the action itself.
3. A small client component for anything interactive (a status switch, a
   form) that calls the server action.

## What's not here yet
- Click-through detail views (shipment/invoice/manifest full record,
  printable) — the prototype has these; porting them here is UI work
  against tables that already exist and are already access-controlled
- File upload (employee photos, POD images) via Supabase Storage
- Real third-party integrations: Google Maps, Twilio, Paystack/Flutterwave,
  WhatsApp, Postmark/Resend, Cloudflare Turnstile
- PDF generation server-side (the prototype's client-side jsPDF approach
  can be ported, or this can move to a server-rendered PDF route)
- Live chat (schema exists: `chat_threads`, `chat_messages`; no UI yet)
