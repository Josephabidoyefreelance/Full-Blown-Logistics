JAAD ERP — Support ticket update fix

IMPORTANT: the earlier ZIP corrected the controls and layout, but your screenshot shows Supabase is refusing to update a ticket. This package includes the missing database policy step as well.

FILES
- src/app/(app)/support/page.tsx
- src/app/(app)/support/actions.ts
- src/app/(app)/support/switches.tsx
- supabase/support-tickets-rls.sql

INSTALL
1. Back up the current Support files.
2. Replace the three Support files in src/app/(app)/support/ with the versions in this package.
3. Open Supabase Dashboard for the same project your local JAAD ERP uses.
4. Open SQL Editor > New query.
5. Open supabase/support-tickets-rls.sql from this package, copy its full contents into SQL Editor, and click Run.
6. Restart the local Next.js server and reload /support?view=tickets.
7. Test changing a ticket priority, resolving it, then reopening it.

SECURITY NOTE
The SQL policy allows any authenticated Supabase user to read and update the shared tickets queue. This is appropriate only if all authenticated JAAD ERP users are trusted staff allowed to manage support tickets. If access should be restricted to particular roles, the policy must be tied to your actual staff-role table; that schema was not included in support.zip, so no role name has been guessed here.

The SQL policy does not use the Supabase service-role key and does not disable RLS. It grants access to authenticated users only.
